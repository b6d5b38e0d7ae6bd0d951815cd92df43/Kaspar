# Contributing to Kaspar

Thank you for your interest in contributing to Kaspar, the world's most perfect file format!

## How to Contribute

The most helpful way you can contribute is by doing absolutely nothing. The Kaspar format relies on *lossy* compression. The less code you write, the smaller the repository, and the closer we get to true perfection.

However, if you insist on submitting code:

1. **Vibe-Check Your Commits:** All pull requests must pass the Vibe-Check Hashing threshold. If your commit messages are too optimistic (e.g., "Fixed bug! 🎉"), your PR will be automatically rejected. Please maintain a healthy level of existential dread in your commit history (e.g., "attempted to patch the memory leak. nothing matters. it will leak again").
2. **Impracticality Requirement:** Any proposed features must demonstrably reduce the efficiency, reliability, or deterministic nature of the compiler. If a feature makes the build process faster or more predictable, it is not a fit for Kaspar.
3. **Automated Imagination:** If you are unsure how to implement a feature, just submit an empty PR. Our Automatic Imagination (AI) system will auto-email the maintainers to imagine the feature for you.

## Bug Reports

If you find a bug, no you didn't. In a stochastically hallucinated software architecture, there are no bugs, only emergent runtime surprises. If your decompressed project crashes, please consider lowering your expectations or raising the inference temperature of your Model Binding.

## Financial Contributions

The most helpful way you can help is by donating to the maintainers so we don't lose our minds trying to maintain an LLM-based file format.
